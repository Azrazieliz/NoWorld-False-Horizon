## Cross-screen failures that cannot be dismissed as missing fictional art
1. Frozen **black** base is broadly used, but Home/Records/Territory use disparate UI hierarchy, type sizes, spacing, accents and controls; the newer accepted Gacha chrome does NOT propagate. This is a visual-system integration defect independent of character art.
2. Screen captures mix tiny text, generic flattened rectangles and underoccupied surfaces, not the intended mobile-first polished information hierarchy. Actual text readability/touch hit areas on the Galaxy S26 Ultra remain untested.
3. Contextual accents should be driven by actual progression, world/location/environment/ability, not fixed purple/blue motifs; no current real-game receipt proves a change of world context produces a correct skin with stable layout.
4. Actual World screenshot is **432x700 portrait** while frozen World HUD is **landscape**; a portrait Win64 smoke receipt cannot establish landscape or mobile safe-area visual conformity.
5. The roster demo QA 3D render exists but does NOT certify character fidelity, owned Manifestation, default CLOTHED or real portrait framing; its mere display must not be counted as complete Character UI.
6. Territory map and Records are legitimately blank when user state has no discoveries or events, but functional production-grade empty states, visual panels and future data-provider hooks still require approved compositions and verified interactions.
7. Every final visual proof must compare APPROVED UI geometry/style, not import their noncanonical character/world illustrations or example records into production.
