# Gate 12 — Next Android App: Mandatory Visible Adult-Mode Acceptance

**Date:** 2026-10-16
**Authority:** Explicit user instruction (newer than historical QA reports).
**Project:** NoWorld: False Horizon, UE 5.8.3, Samsung Galaxy S26 Ultra.

## Decision
The **next private Android app** must expose and let the user personally TEST Adult Mode. Adult-mode runtime tests or textual claims are not substitutes for observable, usable controls. The user has not yet seen the relevant capabilities or any 13-character interaction.

This is an acceptance obligation for the NEXT APP, not proof that it already works. The existing pre-cook hold remains until the user explicitly requests/approves cooking, packaging and installation.

## Mandatory in-app test workflow
1. Discoverable Adult Mode/interaction entry from Ruler, owned-character/roster and embodied World gameplay as supported by the actual context. No debug console knowledge required.
2. Participant selector with legible real character identity, active Version, owned Manifestation/NPC identity and state; choose, add/remove, confirm participants; show protagonist/Ruler as fixed player-side participant.
3. Demonstrate **13 simultaneous persistent logical participants** in one real interaction session, with on-screen roster/count/IDs, valid action roles and sequence state, real-time persistence/clock, and clean exit. Do not claim 13 animated characters merely from logical bindings.
4. Expose selectable authored actions/sequence/pacing, camera, staging/position, interruption and return-to-gameplay. Bind only available genuine character, animation and contextual assets.
5. On-screen before/after verification of actual wardrobe vs effective SFW/Privacy presentation (including Luminous CLOTHED/UNDERWEAR/NUDE where true context/assets permit) without changing authoritative clothes/equipment/owner/state through masking.
6. Show genuine models/rigs and actual per-character overrides when approved packages exist. No generic pawn/mannequin or test characters represented as accepted production content.
7. If some authored actions, meshes, animations, or 13 concurrent rendered animated characters are unavailable, label the specific missing approved Gate01/Gate09/Gate11 assets or mobile-performance constraint clearly; never fake success.
8. Character interaction state, world clock, consequences, exit restoration, interruption/recovery and absence of unintended canonical-save mutations must be demonstrable by the user.

## Required evidence
- Screen recording or reproducible in-game walkthrough from S26 Ultra demonstrating entry, participant count, actor/animation presentation, selected action, pacing and camera, Privacy toggles and ordinary-world return.
- Match against native tests (currently 13 logical participants verified at source level), plus actual Android render/performance/memory profiling. Record simultaneous *visible/animated* character count separately from logical participant count.
- SFW/Privacy must not leak underlying non-SFW visuals during changes, failure states, UI cards or reload.
- No new generic adult-specific currency/reward, forced replay/gallery, invented access/romance/eligibility checks, or mutation of canonical wardrobe under privacy masking. Preserve approved v0.41 architecture and later E03/E04 removals.

## Cross-Gate responsibilities
- Gate12: visible runtime UX entry, participant/session controls, persistence and state-safe integration, mobile device tests.
- Gate09: actual authored animation/action/motion source and synchronization.
- Gate01/Gate11: accepted characters, rig, owned mappings, appearance/wardrobe and adult-compatible assets.
- Gate10: player-facing frozen UI styling and presentation assets.
- Gate02/05/06 as required: staging anchors/world/story/NPC context.

**Gate 00 must track this as a hard acceptance requirement for the next Android test build**, separately from source-only approval and from the authorization to cook. Do not mark adult gameplay DEVICE_PASS solely on 13-participant data-model tests.
