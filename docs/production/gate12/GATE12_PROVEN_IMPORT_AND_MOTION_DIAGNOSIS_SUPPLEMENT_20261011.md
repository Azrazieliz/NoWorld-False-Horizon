### C. WHY the old V1/V2 animation was defective

The user's physical recording showed apparent orthogonal X/Y motion, giant split strides, both legs curling in air, overly smooth rubbery unarticulated limbs, stiff arms, abrupt transitions, poor water motion and camera occlusion. These were mechanics/bone-space/state-machine failures, not cosmetic taste.

1. Existing gameplay movement input is CORRECT: yaw-only controller forward +UE X, right +UE Y via AddMovementInput in AOGWorldPrototypeCharacter. But AOGKoikatsuPlayableCharacter::ComputeState formerly used only horizontal speed magnitude. It never computed signed velocity relative to facing, so lateral, forward and backward could select identical forward Walk/Run animation. Do NOT swap the game's movement X/Y or rotate player controls to hide it.
2. Source GLB is Y-up, geometric face approximately +source Z; Unreal is Z-up and imported visual face approximately +UE Y while actor forward is +UE X. Exact native one-part rig calibration across 21 imported bones: source translation xyz metres becomes UE (x,z,y)*100 cm, source xyzw quaternion becomes UE (-x,-z,-y,w), observed errors below 0.0001 cm and 0.0001 degrees. The original 19 fixture components had Blueprint relative yaw 0; a specific visual mesh yaw correction of -90 degrees is indicated, but must be verified for each source and per component before use.
3. Wrong knee and elbow axes: rejected V2 procedural animation authored bone-local Y rotations on thighs/calves/shoulders/arms. Eight real glTF limb bone length directions were nearly aligned with Y, absolute dot 0.970-0.999, so the supposed flexion was longitudinal twist, NOT anatomical sagittal hip/knee/elbow articulation. Merely changing sine amplitude or globally changing axis to X cannot correct unverified UE imported bone space.
4. Flying was not recognized: the animation state selection handled falling and swimming, but did not check CharacterMovement->IsFlying(). Video after about 56 seconds showed flight, and horizontal flying speed could erroneously play ground Walk/Run, causing airborne legs to fold/split. Jumping and flying require separate diagnosis and animation states.
5. The 171 experimental V1/V2 procedurally synchronized sequences lacked genuine stance/swing mechanics, heel/toe contact, feet planted in world, controlled knee flexion/extension, torso weight transfer, staggered arm/leg motion and natural start/stop. Excessively smooth whole-limb motion was physically unarticulated. Swim was not swimming. Cosmetic smoothing does not fix it.
6. Correct implementation: read signed facing-relative horizontal velocity, acceleration, movement mode, facing, action flags. Build real authored/retargeted animation clips with IK Rig per source skeleton + import basis calibration, validate joint hinges by side-view tests. Create UE Animation Blueprint and 2D Blend Space by speed and signed forward/right for ground; separate starts/stops/pivots, jump takeoff/ascent/fall/land, flying, water/swimming, dodge/combat. One authoritative full-body animation pose distributed to modular compatible skeleton parts via validated Leader Pose or Copy Pose (account for morph, rest poses and mobile cost); add ground-contact-aware IK and synced upper-body/facial layers.
7. Initial isolated direction math tests PASS 16/16 yaw/world direction cases and REJECTED all eight old wrong limb axes; this is not runtime animation approval. CMU original real human BVH walk/jog/jump was preserved with provenance. Three real UE5.8.3 native UAnimSequence on one exact first skeletal component independently cold-verified: Walk 86 frames, Run 44, Jump 121, each 19 native bone tracks. Still no visual full-body / Android approval. Read-only exploration of installed native Koikatsu animation assets confirmed 299 real AnimationClip entries in abdata/action/animator/14.unity3d and 1+4+10 clips in three Studio samples, including swimming; they have real serialized Unity curves but have NOT been baked/imported to UE.
8. Local C++ controller patch adds signed forward/right velocity, a specific -90 visual mesh yaw, direction classes, Flying/FlyingIdle, BUT this is UNBUILT owing to Windows laptop RAM/commit guard. Saved patch at docs/production/gate12/evidence/luminous-v3-continuation-20261011/unbuilt_motion_v3_cpp_changes.patch. Never claim the fix runs until native compilation and physical test pass.
