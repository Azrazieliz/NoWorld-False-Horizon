## How to update progress

When a producer completes or advances a subsystem, update that milestone issue with: (1) the **actual merged/merge-ready game source and asset commit**, (2) the **targeted real native build/package proof**, (3) whether a current **Android APK is ready for the owner's phone testing**, and (4) any concrete blocker. Change its label from `status:backlog` to `status:building`, `status:phone-ready`, or `status:blocked` as applicable. **Only after explicit owner phone acceptance**, set `status:owner-accepted` and close the issue. Do not close an issue based on source work, headless BeginPlay or a PC test.

For M35 (Windows packaging), attach reproducible Windows build/launch evidence; no owner PC testing is requested. Final acceptance of the full game still requires the owner's phone verification of gameplay.

Gate12 owns integration and the playable native UI; Gate00 can maintain status only, not block work. Each Gate can open the linked milestone from a phone without editing this document.
